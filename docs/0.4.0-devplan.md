# Development Plan — Family Planner v0.4.0

> Version: 0.4.0
> Date: May 24, 2026
> References: `docs/architecture.md`, `docs/design.md`, `docs/0.3.0-devplan.md`

---

## Version Goal

v0.4.0 introduces **hybrid display rendering**: the HDMI display keeps the non-headless HTML + Playwright pipeline (unchanged), while the e-ink display completely drops headless Playwright in favor of a native Pillow renderer (`PillowEinkRenderer`).

The change is driven by three structural issues in the current e-ink pipeline:

1. **Headless Playwright on RPi 3B+** uses ~200 MB RAM and requires 3–8 s for each `page.reload()` due to `networkidle` waiting and network font loading.
2. **E-ink navigation** depends indirectly on `PlaywrightRenderer` to access state, creating unnecessary coupling between the e-ink loop and a browser that is never shown.
3. **`PlaywrightRenderer` owns `NavigationState`**, but state must be shared across the e-ink loop, FastAPI routes, and the optional GPIO handler — this coupling is fragile and can cause potential race conditions.

Adopted solution:

- **`StateManager`** (new) — thread-safe singleton that owns `NavigationState`, shared by all system parts via `app.state.state_manager`.
- **`PillowEinkRenderer`** (new) — Pillow renderer that produces `PIL.Image` directly from `NavigationState` + event list, without a browser.
- **`data_builders`** (new module) — extraction of data-preparation logic from `routes/index.py` into a shared module used by Jinja2 routes and the Pillow renderer.
- **`PlaywrightRenderer`** remains, but is instantiated only for `display.type == "hdmi"`.

---

## Invariant Constraints

Constraints from previous versions remain valid. In addition, for v0.4.0:

- `PillowEinkRenderer` uses `tokens.py` exclusively for colors, sizes, and font paths — no hardcoded values
- Fonts are loaded from `app/assets/fonts/` (local TTF) — no network calls during rendering
- SVG icons (Tabler Icons) are **not used** in Pillow rendering — e-ink views use simple geometric symbols or text instead
- `PlaywrightRenderer` is never instantiated when `display.type == "eink"` — the e-ink process does not start Chromium
- `StateManager` is the single source of truth for `NavigationState` — `PlaywrightRenderer` reads/writes state through `StateManager`, not through its own internal lock
- Data-preparation logic (`_event_to_grid`, `_build_month_grid`, etc.) lives in `calendar/data_builders.py`; `routes/index.py` imports it from there

## Phase 1 — StateManager

**Goal:** `NavigationState` is owned by a shared `StateManager` via `app.state.state_manager`. `PlaywrightRenderer` stops owning state; FastAPI routes and the e-ink loop access the same object.

*No dependencies — this phase is the prerequisite for all others.*

### 1.1 — Create `app/renderer/state_manager.py`

New file with the `StateManager` class:

```python
class StateManager:
    def __init__(self) -> None:
        self._state: NavigationState = NavigationState()
        self._lock: threading.Lock = threading.Lock()

    def get(self) -> NavigationState: ...
    def set(self, new_state: NavigationState) -> None: ...
```

- `get()` and `set()` acquire `_lock` — identical to current `PlaywrightRenderer.get_state()` / `update_state()` behavior.
- No navigation logic in the class — `NavigationState.navigate_*()` stays in the immutable dataclass.

**Acceptance criteria:** `StateManager` imports and instantiates without errors; `get()` / `set()` are thread-safe.

### 1.2 — Refactor `app/renderer/playwright_renderer.py`

- Remove `_state` and `_state_lock` from `PlaywrightRenderer`.
- `PlaywrightRenderer.__init__` accepts a `state_manager: StateManager` parameter.
- `get_state()` → `self._state_manager.get()`
- `update_state(new_state)` → `self._state_manager.set(new_state)`

Public methods `get_state()` and `update_state()` remain as thin wrappers for compatibility with existing route code.

**Acceptance criteria:** `PlaywrightRenderer` no longer owns `NavigationState`; observable behavior of `GET /state` and `POST /state` routes is unchanged.

### 1.3 — Inject `StateManager` into `server/app.py`

`create_app()` accepts the new `state_manager: StateManager` parameter and assigns it to `app.state.state_manager`.

```python
app.state.state_manager = state_manager
```

### 1.4 — Update `routes/state.py`

`GET /state` and `POST /state` read state from `request.app.state.state_manager` instead of `request.app.state.renderer.get_state()`. The renderer remains accessible through `request.app.state.renderer` for HDMI cases.

```python
state_manager = request.app.state.state_manager
state = state_manager.get()
# ...
state_manager.set(new_state)
```

**Acceptance criteria:** `curl POST /state -d '{"action":"next"}'` updates state correctly; `GET /state` returns the updated state.

### 1.5 — Update `main.py`

Instantiate `StateManager` before the renderer and pass it to components that require it:

```python
state_manager = StateManager()
renderer = PlaywrightRenderer(config, aggregator, state_manager)   # HDMI only
web_app = create_app(config, aggregator, config_path, renderer, state_manager)
```

|---|---|

def events_range_for_state(state: NavigationState) -> tuple[datetime, datetime]:

Layout constants used by `_event_to_grid` (`_GRID_START_HOUR`, `_GRID_END_HOUR`, `_GRID_HEIGHT_PX`) remain in `data_builders.py` as public module constants so `PillowEinkRenderer` can use them for positioning calculations.

## Phase 3 — PillowEinkRenderer: scaffolding and monthly view

**Goal:** new `renderer/pillow_eink_renderer.py`. Load fonts, define base layout (header + content area + footer), implement full monthly view.

*Depends on: Phase 2 (for `data_builders`).*

### 3.1 — Create `app/renderer/pillow_eink_renderer.py`

Class structure:

```python
class PillowEinkRenderer:
    def __init__(self, config: DisplayConfig) -> None:
        # Load TTF fonts from tokens.FONTS_DIR — once in constructor
        # Determine size from config (width, height) — not from eink model
        # (resizing to physical panel is EinkRenderer responsibility)
        ...

    def render(self, state: NavigationState, events: list[CalendarEvent]) -> Image.Image:
        img = Image.new("RGB", self._size, COLOR_BG)
        draw = ImageDraw.Draw(img)
        self._draw_header(draw, state)
        self._draw_footer(draw)
        match state.view:
            case View.MONTHLY: self._draw_monthly(draw, state, events)
            case View.WEEKLY:  self._draw_weekly(draw, state, events)
            case View.DAILY:   self._draw_daily(draw, state, events)
            case _:            self._draw_monthly(draw, state, events)  # fallback
        return img
```

**Font loading:**

```python
from PIL import ImageFont
from app.renderer.tokens import FONTS_DIR, FONT_DISPLAY_REGULAR, FONT_BODY_REGULAR, ...

self._font_header  = ImageFont.truetype(str(FONTS_DIR / FONT_DISPLAY_REGULAR), TEXT_LG)
self._font_body    = ImageFont.truetype(str(FONTS_DIR / FONT_BODY_REGULAR), TEXT_SM)
self._font_mono    = ImageFont.truetype(str(FONTS_DIR / FONT_MONO_REGULAR), TEXT_XS)
self._font_label   = ImageFont.truetype(str(FONTS_DIR / FONT_BODY_SEMIBOLD), TEXT_XS)
```

If a TTF file does not exist, raise an explicit `FileNotFoundError` with the path — do not use Pillow default font (it produces unreadable output on e-ink).

**Base layout (`_draw_header`, `_draw_footer`):**

- Header: `HEADER_HEIGHT` (56 px) rectangle — view title (e.g. "May 2026") in `font_header`, bottom horizontal separator `COLOR_RULE_STRONG`
- Footer: `FOOTER_HEIGHT` (40 px) rectangle — current view label in `font_label` + selected date in `font_mono`, top separator
- Content area: `(0, HEADER_HEIGHT)` → `(width, height - FOOTER_HEIGHT)`

### 3.2 — Monthly view (`_draw_monthly`)

Use `_build_month_grid(year, month, events, today)` from `data_builders`.

**Layout (for 800×480 with 5 week rows):**

```
content_height = height - HEADER_HEIGHT - FOOTER_HEIGHT  → ~384 px
row_header_height = 20 px  (day labels: MON TUE ... SUN)
cell_height = (content_height - row_header_height) / n_weeks  → ~72 px for 5 rows
cell_width  = width / 7  → ~114 px
```

**Day cell content:**
- Day number: `font_body`, top-left corner of the cell, `COLOR_BG_ALT` background if `is_today`
- Different month: text in `COLOR_INK_FAINT`
- Event dots: for each day `CalendarEvent`, 4 px `●` in `event.color` under day number; max 3 dots + "…" if more than 3
- Grid: `COLOR_RULE` lines between cells (1 px), `COLOR_RULE_STRONG` for outer grid borders

**Acceptance criteria:** `PillowEinkRenderer(config).render(state_monthly, events)` produces an RGB 800×480 image (or configured size) with a readable monthly grid; save with `Image.save()` and inspect visually.

## Phase 4 — PillowEinkRenderer: weekly view

**Goal:** weekly view with time grid and positioned events.

*Depends on: Phase 3 (scaffolding ready).*

### 4.1 — Weekly view (`_draw_weekly`)

Use `_event_to_grid(event, week_start, display_tz)` from `data_builders` to get `top`, `height`, and `day_index` — the same coordinates already computed for the HTML view. The Pillow renderer uses them directly as pixel coordinates in the content area.

**Layout:**

```
time_col_width  = 48 px  (hour labels: 08:00 … 22:00)
day_col_width   = (width - time_col_width) / 7
allday_height   = 20 px  (all-day event strip)
grid_top        = HEADER_HEIGHT + allday_height
grid_height     = content_height - allday_height
```

**Day headers:** top row in the content area with abbreviated day name (`MON`) + day number, bold for current day, `COLOR_BG_ALT` background if today.

**Hour labels:** `font_mono` text on the left, full-width `COLOR_RULE` horizontal lines every hour.

**Event rectangles:** for each event with computed `top` / `height`:
- `ImageDraw.rectangle([(x, grid_top + top), (x + day_col_width - 2, grid_top + top + height)])` with `fill=event.color`
- Event title text in `COLOR_BG` (light text on colored background); truncated if `height < 20 px`
- Start time in `font_mono` if `height >= 28 px`

**All-day strip:** horizontal rectangles proportional to duration, color `event.color`, text in `font_label`.

**Acceptance criteria:** weekly view with at least one overlapping event and one all-day event produces an error-free image, with text and rectangles correctly positioned against the time grid.

## Phase 5 — PillowEinkRenderer: daily view

**Goal:** linear list of daily events.

*Depends on: Phase 3 (scaffolding ready). Parallel with Phase 4.*

### 5.1 — Daily view (`_draw_daily`)

**Layout:** vertical list of events on selected day, ordered by time. Each row:

```
[8px color dot] [HH:MM–HH:MM in font_mono, fixed width 90px] [event title in font_body]
```

`COLOR_RULE` separator (1 px) between rows. If no events: centered "No events" text in `COLOR_INK_FAINT`.

Day date in header (`_draw_header` override): weekday + full date (`Monday, May 24, 2026`).

**Acceptance criteria:** list with 0, 1, and N>10 events (truncated at page end with "+ N more" indicator) produces output without exceptions or visible overflow.

## Phase 6 — Rewire e-ink loop

**Goal:** the e-ink loop uses `PillowEinkRenderer` for rendering; `PlaywrightRenderer` is no longer instantiated for `display.type == "eink"`.

*Depends on: Phase 1, Phase 2, Phase 3–5 (all views implemented).*

### 6.1 — Modify `app/main.py`

**Renderer instantiation condition:**

```python
renderer: PlaywrightRenderer | None = None
pillow_eink_renderer: PillowEinkRenderer | None = None

if config.display.type == "hdmi":
    renderer = PlaywrightRenderer(config, aggregator, state_manager)
elif config.display.type == "eink":
    from app.renderer.pillow_eink_renderer import PillowEinkRenderer
    pillow_eink_renderer = PillowEinkRenderer(config.display)
```

`renderer` remains `None` for e-ink. `create_app()` accepts `renderer: PlaywrightRenderer | None` — HTMX navigation routes do not require renderer to work (they use `state_manager`).

### 6.2 — Modify `_eink_loop` in `main.py`

```python
def _eink_loop(
    state_manager: StateManager,
    pillow_renderer: PillowEinkRenderer,
    eink_post_processor: EinkRenderer,
    display: EinkDisplay,
    aggregator: CalendarAggregator,
    interval: int,
    stop_event: threading.Event,
) -> None:
    while not stop_event.wait(timeout=interval):
        _eink_push(state_manager, pillow_renderer, eink_post_processor, display, aggregator)
```

```python
def _eink_push(...) -> None:
    state = state_manager.get()
    start, end = events_range_for_state(state)
    events = aggregator.get_events(start, end)
    img = pillow_renderer.render(state, events)
    processed = eink_post_processor.process(img)
    display.push(processed)
```

`PlaywrightRenderer.start(port)` and `page.reload()` are fully removed from the e-ink path. No `networkidle` wait, no browser.

### 6.3 — Update `routes/state.py`

`GET /state` and `POST /state` access state through `state_manager` (already done in Phase 1). Remove any reference to `request.app.state.renderer` in state routes — renderer can be `None` for e-ink.

**Acceptance criteria on RPi (or emulated):**
- Process starts without errors with `display.type: "eink"` and no Chromium is launched
- Logs show "E-ink loop started" with no mention of Playwright
- One frame is rendered and (on real hardware) pushed to panel within `refresh_interval`
- `POST /state` updates state; the next loop frame reflects the new view

## Phase 7 — HDMI display cleanup

**Goal:** remove network dependencies from HDMI rendering (Google Fonts → local fonts), remove `page.click()` for GPIO navigation, remove `<meta http-equiv="refresh">` in favor of HTMX polling.

*Depends on: Phase 1 (StateManager). Independent from Phases 3–6.*

### 7.1 — Local fonts in `base.html`

Remove `<link>` tags pointing to `https://fonts.googleapis.com`. Replace with `@font-face` CSS loading TTFs from `/assets/fonts/`:

```html
<style>
  @font-face {
    font-family: 'Playfair Display';
    src: url('/assets/fonts/PlayfairDisplay-Regular.ttf') format('truetype');
    font-weight: 400;
  }
  @font-face {
    font-family: 'Playfair Display';
    src: url('/assets/fonts/PlayfairDisplay-Bold.ttf') format('truetype');
    font-weight: 700;
  }
  @font-face {
    font-family: 'IBM Plex Sans';
    src: url('/assets/fonts/IBMPlexSans-Regular.ttf') format('truetype');
    font-weight: 400;
  }
  @font-face {
    font-family: 'IBM Plex Sans';
    src: url('/assets/fonts/IBMPlexSans-SemiBold.ttf') format('truetype');
    font-weight: 600;
  }
  @font-face {
    font-family: 'IBM Plex Mono';
    src: url('/assets/fonts/IBMPlexMono-Regular.ttf') format('truetype');
    font-weight: 400;
  }
  /* ... rest of CSS unchanged ... */
</style>
```

Also remove `<link rel="preconnect" href="https://fonts.googleapis.com" />` and matching gstatic tag.

**Acceptance criteria:** browser loads page with no Google Fonts requests; fonts appear unchanged.

### 7.2 — HTMX polling instead of `<meta http-equiv="refresh">`

Remove from `base.html`:
```html
<meta http-equiv="refresh" content="{{ refresh_interval }}" />
```

Replace with an HTMX attribute on `<main>` (or equivalent calendar container):

```html
<main id="calendar-root"
      hx-get="/"
      hx-trigger="every {{ refresh_interval }}s"
      hx-target="#calendar-root"
      hx-swap="outerHTML">
```

Meta-refresh caused a full-page reload that could interrupt ongoing navigation. HTMX polling replaces only calendar content, leaving the rest of the page intact (including fixed headers).

**Acceptance criteria:** after `refresh_interval` seconds, calendar content updates without full page reload (verifiable in browser Network tab: no full page request, only `/`).

### 7.3 — GPIO navigation without `page.click()`

Currently, the GPIO handler calls `page.click('#btn-nav-next')` on the Playwright page — 4 layers of indirection (GPIO → Playwright → DOM → HTMX → HTTP).

Replace with a direct HTTP call to `POST /state`:

```python
import urllib.request, json

def _gpio_navigate(action: str, port: int) -> None:
    data = json.dumps({"action": action}).encode()
    req = urllib.request.Request(
        f"http://localhost:{port}/state",
        data=data,
        headers={"Content-Type": "application/json"},
        method="POST",
    )
    urllib.request.urlopen(req, timeout=2)
```

Hidden DOM buttons (`#btn-nav-next`, etc.) remain for touchscreen compatibility, but are no longer the primary GPIO channel.

> **Note:** this task requires a GPIO handler in the project. If it does not exist yet, document the function signature and add a TODO in code without implementing the full handler.

**Acceptance criteria:** next/previous navigation from external script via `curl -X POST /state -d '{"action":"next"}'` updates HDMI browser view within the next HTMX cycle (max `refresh_interval` s).
