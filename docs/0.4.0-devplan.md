# Piano di Sviluppo — Family Planner v0.4.0

> Versione: 0.4.0
> Data: 24 maggio 2026
> Riferimenti: `docs/architecture.md`, `docs/design.md`, `docs/0.3.0-devplan.md`

---

## Obiettivo della versione

v0.4.0 introduce un **rendering ibrido per display**: il display HDMI mantiene la pipeline HTML + Playwright non-headless (invariata), mentre il display e-ink abbandona completamente Playwright headless in favore di un renderer nativo Pillow (`PillowEinkRenderer`).

Il cambiamento è motivato da tre criticità strutturali nella pipeline e-ink attuale:

1. **Playwright headless su RPi 3B+** consuma ~200 MB di RAM e richiede 3–8 s per ogni `page.reload()` a causa dell'attesa `networkidle` e del caricamento font da rete.
2. **La navigazione e-ink** dipende indirettamente da `PlaywrightRenderer` per ottenere lo stato, creando un coupling inutile tra il loop e-ink e un browser che non viene mai visualizzato.
3. **`PlaywrightRenderer` possiede `NavigationState`**, ma lo stato deve essere condiviso tra il loop e-ink, le rotte FastAPI e l'eventuale gestore GPIO — questo accoppiamento è fragile e causa race condition potenziali.

La soluzione adottata:

- **`StateManager`** (nuovo) — singleton thread-safe che possiede `NavigationState`, condiviso tra tutte le parti del sistema via `app.state.state_manager`.
- **`PillowEinkRenderer`** (nuovo) — renderer Pillow che produce `PIL.Image` direttamente da `NavigationState` + lista eventi, senza browser.
- **`data_builders`** (nuovo modulo) — estrazione della logica di preparazione dati da `routes/index.py` in un modulo condiviso tra route Jinja2 e renderer Pillow.
- **`PlaywrightRenderer`** rimane, ma è istanziato solo per `display.type == "hdmi"`.

---

## Vincoli invarianti

I vincoli delle versioni precedenti rimangono validi. In aggiunta, per v0.4.0:

- `PillowEinkRenderer` usa esclusivamente `tokens.py` per colori, dimensioni e percorsi font — nessun valore hardcoded
- I font sono caricati da `app/assets/fonts/` (TTF locali) — nessuna chiamata di rete in fase di rendering
- Le icone SVG (Tabler Icons) **non sono usate** nel rendering Pillow — le viste e-ink usano simboli geometrici elementari o testo al loro posto
- `PlaywrightRenderer` non è mai istanziato quando `display.type == "eink"` — il processo e-ink non avvia Chromium
- `StateManager` è l'unica fonte di verità per `NavigationState` — `PlaywrightRenderer` legge/scrive state via `StateManager`, non con il proprio lock interno
- La logica di preparazione dati (`_event_to_grid`, `_build_month_grid`, ecc.) vive in `calendar/data_builders.py`; `routes/index.py` la importa da lì

## Fase 1 — StateManager

**Goal:** `NavigationState` è posseduto da un `StateManager` condiviso via `app.state.state_manager`. `PlaywrightRenderer` smette di possedere lo stato; le rotte FastAPI e il loop e-ink accedono allo stesso oggetto.

*Nessuna dipendenza — questa fase è il prerequisito per tutte le altre.*

### 1.1 — Creare `app/renderer/state_manager.py`

Nuovo file con la classe `StateManager`:

```python
class StateManager:
    def __init__(self) -> None:
        self._state: NavigationState = NavigationState()
        self._lock: threading.Lock = threading.Lock()

    def get(self) -> NavigationState: ...
    def set(self, new_state: NavigationState) -> None: ...
```

- `get()` e `set()` acquisiscono `_lock` — identico al comportamento attuale di `PlaywrightRenderer.get_state()` / `update_state()`.
- Nessuna logica di navigazione nella classe — `NavigationState.navigate_*()` rimane nel dataclass immutabile.

**Criteri di accettazione:** `StateManager` importa e istanzia senza errori; `get()` / `set()` sono thread-safe.

### 1.2 — Refactor `app/renderer/playwright_renderer.py`

- Rimuovere `_state` e `_state_lock` da `PlaywrightRenderer`.
- `PlaywrightRenderer.__init__` accetta un parametro `state_manager: StateManager`.
- `get_state()` → `self._state_manager.get()`
- `update_state(new_state)` → `self._state_manager.set(new_state)`

I metodi pubblici `get_state()` e `update_state()` rimangono come thin wrapper per compatibilità con il codice esistente nelle route.

**Criteri di accettazione:** `PlaywrightRenderer` non possiede più `NavigationState`; il comportamento osservabile delle rotte `GET /state` e `POST /state` è invariato.

### 1.3 — Iniettare `StateManager` in `server/app.py`

`create_app()` accetta il nuovo parametro `state_manager: StateManager` e lo assegna ad `app.state.state_manager`.

```python
app.state.state_manager = state_manager
```

### 1.4 — Aggiornare `routes/state.py`

`GET /state` e `POST /state` leggono lo stato da `request.app.state.state_manager` invece che da `request.app.state.renderer.get_state()`. Il renderer rimane accessibile tramite `request.app.state.renderer` per i casi HDMI.

```python
state_manager = request.app.state.state_manager
state = state_manager.get()
# ...
state_manager.set(new_state)
```

**Criteri di accettazione:** `curl POST /state -d '{"action":"next"}'` aggiorna lo stato correttamente; `GET /state` restituisce il nuovo stato.

### 1.5 — Aggiornare `main.py`

Istanziare `StateManager` prima del renderer e passarlo ai componenti che lo richiedono:

```python
state_manager = StateManager()
renderer = PlaywrightRenderer(config, aggregator, state_manager)   # solo per HDMI
web_app = create_app(config, aggregator, config_path, renderer, state_manager)
```

## Fase 3 — PillowEinkRenderer: scaffolding e vista mensile

**Goal:** nuovo `renderer/pillow_eink_renderer.py`. Carica font, definisce il layout base (header + content area + footer), implementa la vista mensile completa.

*Dipende da: Fase 2 (per `data_builders`).*

### 3.1 — Creare `app/renderer/pillow_eink_renderer.py`

Struttura della classe:

```python
class PillowEinkRenderer:
    def __init__(self, config: DisplayConfig) -> None:
        # Carica font TTF da tokens.FONTS_DIR — una volta sola al costruttore
        # Determina size dal config (width, height) — non dal modello eink
        # (il ridimensionamento al pannello fisico è compito di EinkRenderer)
        ...

    def render(self, state: NavigationState, events: list[CalendarEvent]) -> Image.Image:
        img = Image.new("RGB", self._size, COLOR_BG)
        draw = ImageDraw.Draw(img)
        self._draw_header(draw, state)
        self._draw_footer(draw)
        match state.view:
            case View.MONTHLY: self._draw_monthly(draw, state, events)
            case View.WEEKLY:  self._draw_weekly(draw, state, events)
            case View.DAILY:   self._draw_daily(draw, state, events)
            case _:            self._draw_monthly(draw, state, events)  # fallback
        return img
```

**Caricamento font:**

```python
from PIL import ImageFont
from app.renderer.tokens import FONTS_DIR, FONT_DISPLAY_REGULAR, FONT_BODY_REGULAR, ...

self._font_header  = ImageFont.truetype(str(FONTS_DIR / FONT_DISPLAY_REGULAR), TEXT_LG)
self._font_body    = ImageFont.truetype(str(FONTS_DIR / FONT_BODY_REGULAR), TEXT_SM)
self._font_mono    = ImageFont.truetype(str(FONTS_DIR / FONT_MONO_REGULAR), TEXT_XS)
self._font_label   = ImageFont.truetype(str(FONTS_DIR / FONT_BODY_SEMIBOLD), TEXT_XS)
```

Se un file TTF non esiste, sollevare `FileNotFoundError` esplicito con il percorso — non usare il font di default Pillow (produce output illeggibile su e-ink).

**Layout base (`_draw_header`, `_draw_footer`):**

- Header: rettangolo alto `HEADER_HEIGHT` (56 px) — titolo della vista (es. "Maggio 2026") in `font_header`, separatore orizzontale `COLOR_RULE_STRONG` in basso
- Footer: rettangolo alto `FOOTER_HEIGHT` (40 px) — etichetta vista corrente in `font_label` + data selezionata in `font_mono`, separatore in cima
- Content area: `(0, HEADER_HEIGHT)` → `(width, height - FOOTER_HEIGHT)`

### 3.2 — Vista mensile (`_draw_monthly`)

Usa `_build_month_grid(year, month, events, today)` da `data_builders`.

**Layout (per 800×480 con 5 righe settimana):**

```
content_height = height - HEADER_HEIGHT - FOOTER_HEIGHT  → ~384 px
row_header_height = 20 px  (nomi giorno: LUN MAR ... DOM)
cell_height = (content_height - row_header_height) / n_weeks  → ~72 px per 5 righe
cell_width  = width / 7  → ~114 px
```

**Contenuto cella giorno:**
- Numero del giorno: `font_body`, angolo in alto a sinistra della cella, sfondo `COLOR_BG_ALT` se `is_today`
- Mese diverso: testo in `COLOR_INK_FAINT`
- Punti evento: per ogni `CalendarEvent` della giornata, cerchio `●` di 4 px nel colore `event.color` sotto il numero del giorno; max 3 punti + "…" se ce ne sono più di 3
- Griglia: linee `COLOR_RULE` tra celle (1 px), `COLOR_RULE_STRONG` per i bordi esterni della griglia

**Criteri di accettazione:** `PillowEinkRenderer(config).render(state_monthly, events)` produce un'immagine RGB 800×480 (o dimensione configurata) con una griglia mensile leggibile; salvare con `Image.save()` e ispezionare visivamente.

## Fase 4 — PillowEinkRenderer: vista settimanale

**Goal:** vista settimanale con griglia oraria e eventi posizionati.

*Dipende da: Fase 3 (scaffolding pronto).*

### 4.1 — Vista settimanale (`_draw_weekly`)

Usa `_event_to_grid(event, week_start, display_tz)` da `data_builders` per ottenere `top`, `height` e `day_index` — le stesse coordinate già calcolate per la vista HTML. Il renderer Pillow le usa direttamente come coordinate pixel nella content area.

**Layout:**

```
time_col_width  = 48 px  (etichette ore: 08:00 … 22:00)
day_col_width   = (width - time_col_width) / 7
allday_height   = 20 px  (striscia eventi tutto-il-giorno)
grid_top        = HEADER_HEIGHT + allday_height
grid_height     = content_height - allday_height
```

**Intestazioni giorno:** fila in cima alla content area con nome giorno abbreviato (`LUN`) + numero, in grassetto per il giorno corrente, sfondo `COLOR_BG_ALT` se è oggi.

**Etichette ore:** testo `font_mono` a sinistra, linee orizzontali `COLOR_RULE` a tutta larghezza ogni ora.

**Rettangoli evento:** per ogni evento con `top` / `height` calcolati:
- `ImageDraw.rectangle([(x, grid_top + top), (x + day_col_width - 2, grid_top + top + height)])` con `fill=event.color`
- Testo titolo evento in `COLOR_BG` (testo chiaro su sfondo colorato); troncato se `height < 20 px`
- Ora inizio in `font_mono` se `height >= 28 px`

**Striscia eventi tutto-il-giorno:** rettangoli orizzontali proporzionali alla durata, colore `event.color`, testo in `font_label`.

**Criteri di accettazione:** vista settimanale con almeno un evento sovrapposto e un evento tutto-il-giorno produce un'immagine senza errori, con testo e rettangoli in posizione corretta rispetto alla griglia oraria.

## Fase 5 — PillowEinkRenderer: vista giornaliera

**Goal:** lista lineare degli eventi del giorno.

*Dipende da: Fase 3 (scaffolding pronto). Parallela a Fase 4.*

### 5.1 — Vista giornaliera (`_draw_daily`)

**Layout:** lista verticale degli eventi del giorno selezionato, ordinati per orario. Ogni riga:

```
[punto colore 8px] [HH:MM–HH:MM in font_mono, larghezza fissa 90px] [titolo evento in font_body]
```

Separatore `COLOR_RULE` (1 px) tra righe. Se non ci sono eventi: testo "Nessun evento" centrato in `COLOR_INK_FAINT`.

**Criteri di accettazione:** lista con 0, 1 e N>10 eventi (troncata a fine pagina con indicatore "+ N altri") produce output senza eccezioni né overflow visibile.

## Fase 6 — Rewiring loop e-ink

**Goal:** il loop e-ink usa `PillowEinkRenderer` per il rendering; `PlaywrightRenderer` non è più istanziato per `display.type == "eink"`.

*Dipende da: Fase 1, Fase 2, Fase 3–5 (tutte le viste implementate).*

### 6.1 — Modificare `app/main.py`

**Condizione istanziazione renderer:**

```python
renderer: PlaywrightRenderer | None = None
pillow_eink_renderer: PillowEinkRenderer | None = None

if config.display.type == "hdmi":
    renderer = PlaywrightRenderer(config, aggregator, state_manager)
elif config.display.type == "eink":
    from app.renderer.pillow_eink_renderer import PillowEinkRenderer
    pillow_eink_renderer = PillowEinkRenderer(config.display)
```

`renderer` rimane `None` per e-ink. `create_app()` accetta `renderer: PlaywrightRenderer | None` — le rotte HTMX di navigazione non richiedono il renderer per funzionare (usano `state_manager`).

### 6.2 — Modificare `_eink_loop` in `main.py`

```python
def _eink_loop(
    state_manager: StateManager,
    pillow_renderer: PillowEinkRenderer,
    eink_post_processor: EinkRenderer,
    display: EinkDisplay,
    aggregator: CalendarAggregator,
    interval: int,
    stop_event: threading.Event,
) -> None:
    while not stop_event.wait(timeout=interval):
        _eink_push(state_manager, pillow_renderer, eink_post_processor, display, aggregator)
```

```python
def _eink_push(...) -> None:
    state = state_manager.get()
    start, end = events_range_for_state(state)
    events = aggregator.get_events(start, end)
    img = pillow_renderer.render(state, events)
    processed = eink_post_processor.process(img)
    display.push(processed)
```

Il metodo `PlaywrightRenderer.start(port)` e il `page.reload()` sono completamente rimossi dal percorso e-ink. Nessuna attesa `networkidle`, nessun browser.

### 6.3 — Aggiornare `routes/state.py`

`GET /state` e `POST /state` accedono allo stato via `state_manager` (già fatto in Fase 1). Rimuovere ogni riferimento a `request.app.state.renderer` nelle rotte di stato — il renderer può essere `None` per e-ink.

**Criteri di accettazione su RPi (o emulato):**
- Il processo avvia senza errori con `display.type: "eink"` e nessun Chromium viene lanciato
- Il log mostra "E-ink loop started" senza menzione di Playwright
- Un frame viene renderizzato e (su hardware reale) pushato al pannello entro `refresh_interval`
- `POST /state` aggiorna lo stato; il frame successivo del loop riflette la nuova vista

## Fase 7 — Cleanup display HDMI

**Goal:** rimuovere le dipendenze di rete dal rendering HDMI (Google Fonts → font locali), eliminare `page.click()` per la navigazione GPIO, rimuovere `<meta http-equiv="refresh">` in favore di HTMX polling.

*Dipende da: Fase 1 (StateManager). Indipendente dalle Fasi 3–6.*

    src: url('/assets/fonts/IBMPlexSans-SemiBold.ttf') format('truetype');

Rimuovere anche `<link rel="preconnect" href="https://fonts.googleapis.com" />` e il tag gstatic corrispondente.

**Criteri di accettazione:** il browser carica la pagina senza richieste a Google Fonts; i font appaiono invariati.

### 7.2 — HTMX polling al posto di `<meta http-equiv="refresh">`

Rimuovere da `base.html`:
```html
<meta http-equiv="refresh" content="{{ refresh_interval }}" />
```

Sostituire con un attributo HTMX sull'elemento `<main>` (o equivalente contenitore del calendario):

```html
<main id="calendar-root"
      hx-get="/"
      hx-trigger="every {{ refresh_interval }}s"
      hx-target="#calendar-root"
      hx-swap="outerHTML">
```

Il meta-refresh faceva un full-page reload che poteva interrompere navigazioni in corso. HTMX polling sostituisce solo il contenuto del calendario, lasciando intatto il resto della pagina (inclusi header fissi).

**Criteri di accettazione:** dopo `refresh_interval` secondi, il contenuto del calendario si aggiorna senza reload completo della pagina (verificabile con Network tab del browser: nessuna richiesta all'intera pagina, solo a `/`).

### 7.3 — Navigazione GPIO senza `page.click()`

Attualmente il gestore GPIO chiama `page.click('#btn-nav-next')` sulla pagina Playwright — 4 livelli di indirezione (GPIO → Playwright → DOM → HTMX → HTTP).

Sostituire con una chiamata HTTP diretta a `POST /state`:

```python
import urllib.request, json

def _gpio_navigate(action: str, port: int) -> None:
    data = json.dumps({"action": action}).encode()
    req = urllib.request.Request(
        f"http://localhost:{port}/state",
        data=data,
        headers={"Content-Type": "application/json"},
        method="POST",
    )
    urllib.request.urlopen(req, timeout=2)
```

I pulsanti nascosti nel DOM (`#btn-nav-next`, ecc.) rimangono per compatibilità con touchscreen, ma non sono più il canale principale per GPIO.

> **Nota:** questo task richiede la presenza di un gestore GPIO nel progetto. Se non esiste ancora, documentare la firma della funzione e aggiungere un TODO nel codice senza implementare il gestore completo.

**Criteri di accettazione:** la navigazione avanzamento/retrocessione da script esterno tramite `curl -X POST /state -d '{"action":"next"}'` aggiorna la vista nel browser HDMI entro il prossimo ciclo HTMX (max `refresh_interval` s).

## Criteri di accettazione globali (smoke test)

1. **HDMI:** `python app/main.py --config config/default.yaml` con `display.type: hdmi` avvia senza errori; il browser mostra la vista settimanale; navigazione via pulsanti funziona.
2. **E-ink (simulato):** `display.type: eink` avvia senza Chromium nel log; `PillowEinkRenderer.render()` produce un'immagine valida salvabile su disco; nessun errore `ImportError` per Waveshare su macOS.
3. **Navigazione da API:** `POST /state` con azioni `prev/next/in/out/night` aggiorna lo stato; `GET /state` conferma la modifica.
4. **Font offline:** rete disconnessa; HDMI carica i font correttamente da `/assets/fonts/`.
5. **Memoria RPi:** con `display.type: eink`, il processo non supera 120 MB RSS su RPi 4 (verificabile con `ps aux`).
