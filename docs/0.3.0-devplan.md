# Development Plan - Family Planner v0.3.0

> Version: 0.3.0
> Date: May 23, 2026
> References: `docs/architecture.md`, `docs/design.md`, `docs/0.2.0-devplan.md`

---

## Version Goal

v0.3.0 completes the project in two sequential phases:

1. **Complete v0.2.0** - closes all truncated files and missing route handlers left incomplete at the end of v0.2.0 (HTML templates, ICS provider, config route).
2. **Migrate to PlaywrightRenderer** - replaces `ImageRenderer` (Pillow) with `PlaywrightRenderer` (headless Chromium via Playwright) as the single rendering source, aligning the codebase with the architecture described in `docs/architecture.md`. Jinja2 HTML templates become the visual source of truth for both displays. `HdmiDisplay` is refactored from a Chromium subprocess approach to non-headless Playwright. HTMX is wired for navigation.

---

## Invariant Constraints (must be respected in every phase)

- `PlaywrightRenderer` is the single rendering source - no duplicated Pillow rendering for physical displays
- Waveshare libraries are always imported dynamically, guarded by `display.type == "eink"`
- `playwright_executable` is configurable (`null` = Playwright bundle; `/usr/bin/chromium-browser` on Raspberry Pi)
- CalDAV/iCal credentials never appear in logs, API output, or error messages
- All file paths use `pathlib.Path`
- Standard logging (`logging`) - no diagnostic `print`
- Type hints are mandatory on all public functions
- No `box-shadow`, `border-radius`, or `text-shadow` in HTML templates
- CSS uses only `px` - no `rem`, `em`, `vw`, `vh`
- HTMX is included as a local asset in `base.html` - it is not a pip package

## Phase 2 - HTMX: Navigation Wiring

**Goal:** footer buttons in `base.html` send navigation actions to the server via HTMX; the DOM updates without full-page reload. Hidden buttons with specific IDs are present in the DOM for Playwright `page.click()`.

*Depends on: Phase 1 (complete route handlers).*

### 2.1 - Add HTMX as local asset

**File:** `app/assets/htmx.min.js` (download htmx 2.x from https://htmx.org/dist/htmx.min.js)

Register `app/assets/` as `StaticFiles` in `app/server/app.py`:
```python
from fastapi.staticfiles import StaticFiles
app.mount("/assets", StaticFiles(directory=str(Path(__file__).parent.parent / "assets")), name="assets")
```

**Acceptance criteria:** `GET /assets/htmx.min.js` returns 200.

### 2.2 - Load HTMX and add navigation buttons in `base.html`

**File:** `app/server/templates/base.html`

1. Add in `<head>`:
   ```html
   <script src="/assets/htmx.min.js" defer></script>
   ```

2. Add inside `<body>`, before `</body>`, a navigation overlay visible only when `show_buttons` is true:
   ```html
   <div class="nav-overlay {{ '' if show_buttons else 'nav-overlay--hidden' }}">
     <button id="btn-nav-out"   hx-post="/state" hx-vals='{"action":"out"}'   hx-target="body" hx-swap="outerHTML" type="button">↑</button>
     <button id="btn-nav-prev"  hx-post="/state" hx-vals='{"action":"prev"}'  hx-target="body" hx-swap="outerHTML" type="button">←</button>
     <button id="btn-nav-next"  hx-post="/state" hx-vals='{"action":"next"}'  hx-target="body" hx-swap="outerHTML" type="button">→</button>
     <button id="btn-nav-in"    hx-post="/state" hx-vals='{"action":"in"}'    hx-target="body" hx-swap="outerHTML" type="button">↓</button>
     <button id="btn-nav-night" hx-post="/state" hx-vals='{"action":"night"}' hx-target="body" hx-swap="outerHTML" type="button">☾</button>
   </div>
   ```
   `.nav-overlay--hidden` applies `visibility: hidden; pointer-events: none` - buttons remain in the DOM for `page.click()`.

**Acceptance criteria:** clicking a browser button updates the view without full reload; `show_buttons: false` hides buttons visually but keeps them in the DOM.

### 2.3 - Update `POST /state` to return HTML

**File:** `app/server/routes/state.py`

After state update, `POST /state` must return the HTML content of the new view (same as `GET /`). Extract rendering logic from `routes/index.py` into a shared function `_render_view(request) -> TemplateResponse`, used by both `GET /` and `POST /state`.

HTMX request detection via `HX-Request: true` header:
```python
if request.headers.get("HX-Request"):
    return await _render_view(request)
return JSONResponse(new_state.model_dump())
```

**Acceptance criteria:** a `POST /state` with `{"action": "next"}` returns HTML 200 with the new view; HTMX replaces `<body>` correctly.

## Phase 3 - PlaywrightRenderer

**Goal:** new `app/renderer/playwright_renderer.py` keeps a persistent headless Chromium instance, handles `NavigationState` with thread safety, and produces `PIL.Image` via screenshot.

*Depends on: Phase 2 (HTMX + updated /state route).*

### 3.1 - Create `app/renderer/playwright_renderer.py`

**Class `PlaywrightRenderer`** - implements `app/renderer/base.py` interface:

```python
class PlaywrightRenderer:
    def __init__(self, config: AppConfig, aggregator: CalendarAggregator) -> None: ...
    def start(self, port: int) -> None: ...         # launch Playwright headless
    def screenshot(self) -> Image.Image: ...         # page.reload() + screenshot -> PIL.Image
    def get_state(self) -> NavigationState: ...      # thread-safe read
    def update_state(self, new_state: NavigationState) -> None: ...  # thread-safe write
    def click_nav(self, action: str) -> None: ...    # page.click(f"#btn-nav-{action}")
    def stop(self) -> None: ...                      # browser.close()
```

**Implementation details:**
- Startup: `sync_playwright().start()` -> `playwright.chromium.launch(headless=True, executable_path=...)` -> `browser.new_context(viewport={"width": W, "height": H})` -> `page.goto(url)`
- Screenshot: `page.reload(wait_until="networkidle")` -> `data = page.screenshot(full_page=False)` -> `PIL.Image.open(io.BytesIO(data))`
- Thread safety: `_state_lock` protects `_state`; `_page_lock` protects the full `page.reload() + page.screenshot()` sequence
- `_wait_for_server()`: poll `http://localhost:{port}/` every 0.5s with 30s timeout

**Acceptance criteria:**
- `PlaywrightRenderer.screenshot()` returns an RGB `PIL.Image` sized `config.display.width × config.display.height`
- `get_state()` / `update_state()` are thread-safe
- On macOS, without `playwright_executable`, it uses the Playwright bundle without errors

### 3.2 - Update `app/renderer/__init__.py`

```python
from app.renderer.playwright_renderer import PlaywrightRenderer

__all__ = ["PlaywrightRenderer"]
```

**Acceptance criteria:** `from app.renderer import PlaywrightRenderer` works.

## Phase 4 - Refactor HdmiDisplay

**Goal:** `HdmiDisplay` uses non-headless Playwright Python API instead of Chromium subprocess.

*Depends on: Phase 3.*

### 4.1 - Rewrite `app/display/hdmi.py`

**Remove:** `subprocess`, `shutil` imports; `_find_chromium()`, `_build_command()` methods; `_proc` attribute.

**Add:** `from playwright.sync_api import sync_playwright`; `_playwright`, `_browser`, `_page` attributes.

**`start()` refactor:**
```
HdmiDisplay.start()
  -> daemon thread _run() that:
      -> sync_playwright().start()
      -> chromium.launch(headless=False, args=[...])
      -> context.new_page().goto(url)
      -> stop_event.wait()  # blocks thread until stop() is called
```

**Threading note:** `sync_playwright()` must be started and used by the same thread. `_run()` is the dedicated daemon thread owning the Playwright context.

**Acceptance criteria:**
- `fullscreen: false` -> Chromium window at `width × height` on macOS
- `fullscreen: true` + `playwright_executable: /usr/bin/chromium-browser` -> kiosk on Raspberry Pi
- `HdmiDisplay.stop()` closes the window without errors

## Considerations

### Threading and Playwright sync API

Playwright `sync_playwright()` is not thread-safe. Use two separate locks in `PlaywrightRenderer`:
- `_state_lock`: protects read/write of `_state`
- `_page_lock`: protects the full `page.reload() + page.screenshot()` sequence

If `update_state()` and `screenshot()` are called concurrently (FastAPI POST /state + e-ink loop), locks serialize operations. Overhead is acceptable for intervals >= 60s.

### HTMX and full vs partial updates

The chosen approach (POST /state returns the entire new page, HTMX replaces `<body>`) is simpler than partial updates and works correctly for all use cases: HDMI (DOM updates via HTMX) and e-ink (`page.reload()` on next screenshot cycle).

### HdmiDisplay and dedicated thread

`sync_playwright()` must be started and used by the same OS thread. `HdmiDisplay._run()` is the dedicated daemon thread that owns the Playwright context; `start()` launches the thread and returns immediately.
