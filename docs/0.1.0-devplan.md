# Development Plan — Family Planner v0.1.0

> Version: 0.1.0  
> Date: May 23, 2026  
> References: `docs/architecture.md`, `docs/design.md`

---

## Version Objective

Complete implementation of the system running on an HDMI display (pygame), with iCloud CalDAV support and local ICS files, a FastAPI web server for preview and configuration, and all five calendar views (annual, monthly, weekly, daily, event detail).

The e-ink display is within scope but treated as a post-processing layer — the infrastructure is built, but testing on physical hardware is out of scope for this version.

---

## Invariant Constraints (must be respected in every phase)

- No `box-shadow`, `text-shadow`, `border-radius` in HTML templates or the Pillow renderer
- Waveshare libraries are always imported dynamically, guarded by `display.type == "eink"`
- `ImageRenderer` is shared by both displays — no duplication of rendering logic
- CalDAV credentials must never appear in logs, API output, or error messages
- All file paths use `pathlib.Path`
- Standard `logging` module — no diagnostic `print` statements
- Type hints required on all public functions

class ServerConfig(BaseModel):
    host: str = "0.0.0.0"

    type: Literal["hdmi", "eink"] = "hdmi"

## Phase 2 — Calendar Layer

**Goal:** fetch and normalise events from different sources.

### 2.1 — Abstract class `CalendarProvider` (`app/calendar/base.py`)

```python
from abc import ABC, abstractmethod
from dataclasses import dataclass
from datetime import datetime

@dataclass
class CalendarEvent:
    uid: str
    title: str
    start: datetime
    end: datetime
    all_day: bool
    location: str | None
    description: str | None
    attendees: list[str]
    recurrent: bool
    color: str              # inherited from provider
    calendar_name: str

class CalendarProvider(ABC):
    @abstractmethod
    def fetch_events(self, start: datetime, end: datetime) -> list[CalendarEvent]: ...

    @abstractmethod
    def test_connection(self) -> bool: ...
```

### 2.2 — Local ICS provider (`app/calendar/ics_provider.py`)

- Reads `.ics` files from `path` (supports relative and absolute paths via `pathlib.Path`)
- Uses the `icalendar` library for parsing
- Handles recurring events with expansion within the `[start, end]` range
- Handles `VTIMEZONE` and normalisation to aware `datetime` objects
- `test_connection()`: verifies the file exists
- Exception handling: `FileNotFoundError`, `ValueError` for malformed ICS — log and return empty list, no crash

### 2.3 — CalDAV provider (`app/calendar/caldav_provider.py`)

- Connects to `url` with `username` / `password` via the `caldav` library
- Automatic discovery of available calendars on the account
- Fetches events in the `[start, end]` range with server-side date filtering (no full download)
- **Security:** the password must never appear in logs — use safe `repr` or redacting in logging
- `test_connection()`: attempts a lightweight `PROPFIND`, returns `bool`
- Specific exception handling: `caldav.DAVError`, `requests.ConnectionError`, `AuthorizationError`
- Configurable timeout (default: 15 seconds)

### 2.4 — `CalendarAggregator` (`app/calendar/aggregator.py`)

- Instantiates providers from `list[CalendarConfig]` (internal factory)
- `get_events(start: datetime, end: datetime) -> list[CalendarEvent]`: calls all providers in parallel (`ThreadPoolExecutor`), aggregates, sorts by `start`
- Failed providers: log the error, return partial result (does not block the others)
- TTL cache equal to `display.refresh_interval` to avoid redundant fetches on close HDMI refreshes

### 3.4 — `ImageRenderer` (`app/renderer/image_renderer.py`)

Main class. Depends on `CalendarAggregator`, `NavigationState`, `DisplayConfig`.

**Internal structure:**

```python
class ImageRenderer(Renderer):
    def __init__(self, aggregator, config: DisplayConfig, state: NavigationState): ...

    def render(self) -> Image.Image:
        img = Image.new("RGB", (self.width, self.height), self._palette["COLOR_BG"])
        draw = ImageDraw.Draw(img)
        self._draw_header(draw, img)
        self._draw_footer(draw, img)
        self._draw_content(draw, img)
        return img

    def _draw_header(self, draw, img): ...
    def _draw_footer(self, draw, img): ...
    def _draw_content(self, draw, img):
        # dispatch for current view
        match self.state.view:
            case View.ANNUAL:   self._draw_annual(draw, img)
            case View.MONTHLY:  self._draw_monthly(draw, img)
            case View.WEEKLY:   self._draw_weekly(draw, img)
            case View.DAILY:    self._draw_daily(draw, img)
            case View.DETAIL:   self._draw_detail(draw, img)
```

**View methods — rendering specifications:**

#### `_draw_annual`
- 4×3 grid of mini-calendars
- Each mini-calendar: uppercase month heading `TEXT_SM`, day numbers `TEXT_XS`
- Selected month: `2px COLOR_RULE_STRONG` outline
- Today: `16×16px` square with `COLOR_ACCENT` background, `COLOR_BG` text
- Holidays: number in `font-weight bold`, dot `·` below

#### `_draw_monthly`
- 7 columns (Mon–Sun), uppercase headings `TEXT_SM`
- Week rows separated by `1px COLOR_RULE`
- Selected week: `COLOR_BG_ALT` background, `2px COLOR_RULE_STRONG` top/bottom borders
- Today: `28×28px` square with `COLOR_ACCENT` background
- Days with events: dash `—` below the number, `COLOR_INK_MUTED`
- Days from previous/next month: `COLOR_INK_FAINT`

#### `_draw_weekly`
- Left time column: fixed width `52px`, `FONT_MONO TEXT_XS COLOR_INK_MUTED`
- Day columns: equal remaining width divided by 7
- Time grid: 08:00–22:00 default (configurable in future version)
- Event blocks: `1px COLOR_RULE_STRONG` rectangle, `COLOR_BG_ALT` background
- Selected event: `2px COLOR_RULE_STRONG`, `COLOR_ACCENT` background, `COLOR_BG` text
- Current time row: horizontal `1px COLOR_ACCENT` line
- All-day strip: `24px` height above the grid, `1px COLOR_RULE_STRONG` below
- Current day column header: inverted colours

#### `_draw_daily`
- Left time strip: width `56px`, `FONT_MONO TEXT_SM COLOR_INK_MUTED`, right-aligned
- Each event: block with `1px COLOR_RULE` border-top
- Title: `FONT_BODY TEXT_BASE weight=600`
- Time range: `TEXT_SM COLOR_INK_MUTED`
- Selected event: `COLOR_BG_ALT` background, `3px COLOR_RULE_STRONG` left border
- Free slot ≥ 60 min: row `──── Free ────` in `COLOR_INK_FAINT TEXT_XS`
- Event overflow: "page" effect — no scroll, full content area replacement

#### `_draw_detail`
- Title: `FONT_DISPLAY TEXT_XL uppercase bold`
- Double-line `═` separators above and below the title
- Info rows: icon (loaded as rasterised PNG/SVG `16px`) + text `FONT_BODY TEXT_BASE`
- NOTES section: `1px COLOR_RULE` border-top, scrollable area managed via `detail_scroll_offset`
- Overflow indicator `▼` in `COLOR_INK_FAINT` when notes exceed available space

**Fonts:** load from `.ttf` files in `app/assets/fonts/`. If absent, fall back to PIL built-in fonts with a warning.

**Icons:** rasterise Tabler SVGs at `16px` / `20px` / `24px` via Pillow `Image.open()` on pre-converted PNGs in `app/assets/icons/`. A separate conversion script is out of scope — PNG icons are static assets.

### 3.5 — `EinkRenderer` (`app/renderer/eink_renderer.py`)

Post-processing on the `PIL.Image` received from `ImageRenderer`:

1. Resize to the panel's native resolution (`eink_model` → dictionary of known resolutions)
2. Palette quantisation:
   - `bw`: `image.convert("1")` then `convert("RGB")`
   - `bwr`: custom 3-colour palette (white, black, red)
   - `4gray`: 4 equidistant grey levels
3. Floyd-Steinberg dithering: `Image.Dither.FLOYDSTEINBERG` if `eink_dither: true`
4. Returns a `PIL.Image` ready to be pushed to the panel

## Phase 4 — Display Layer

**Goal:** the rendered image is sent to the screen (HDMI) or the physical panel (e-ink).

### 4.1 — `HdmiDisplay` (`app/display/hdmi.py`)

```python
class HdmiDisplay:
    def __init__(self, config: DisplayConfig, renderer: ImageRenderer,
                 aggregator: CalendarAggregator): ...

    def start(self) -> None:
        # starts the pygame loop in a separate thread
        threading.Thread(target=self._loop, daemon=True).start()

    def _loop(self) -> None:
        pygame.init()
        flags = pygame.FULLSCREEN if self.fullscreen else 0
        screen = pygame.display.set_mode((self.width, self.height), flags)
        clock = pygame.time.Clock()
        while self._running:
            for event in pygame.event.get():
                if event.type == pygame.QUIT:
                    self._running = False
                elif event.type == pygame.KEYDOWN:
                    self._handle_key(event.key)
            image = self.renderer.render()
            surface = pygame.image.frombuffer(
                image.tobytes(), image.size, image.mode)
            screen.blit(surface, (0, 0))
            pygame.display.flip()
            clock.tick(1 / self.refresh_interval)
        pygame.quit()

    def _handle_key(self, key: int) -> None:
        # mapping K_ESCAPE→escape, K_UP→up, K_DOWN→down, K_RETURN→enter
        # updates NavigationState and calls renderer.update_state(new_state)

    def stop(self) -> None:
        self._running = False
```

Key mapping → navigation actions (from `docs/design.md`):

| `pygame.key` | Action |
|---|---|
| `K_ESCAPE` | `navigate_escape()` |
| `K_UP` | `navigate_up()` |
| `K_DOWN` | `navigate_down()` |
| `K_RETURN` | `navigate_enter()` |

Night mode: toggle via `K_n` key (HDMI only) — updates `NavigationState.night_mode`.

## Phase 5 — Web Server

**Goal:** working web preview of the calendar and configuration interface in the browser.

### 5.1 — FastAPI app (`app/server/app.py`)

```python
def create_app(config: AppConfig, aggregator: CalendarAggregator) -> FastAPI:
    app = FastAPI(title="Family Planner")
    app.include_router(index_router)
    app.include_router(config_router)
    templates = Jinja2Templates(directory=Path(__file__).parent / "templates")
    app.state.config = config
    app.state.aggregator = aggregator
    app.state.templates = templates
    return app
```

### 5.2 — `GET /` route (`app/server/routes/index.py`)

- Fetches events for the current week from `aggregator`
- Renders `calendar.html` with event context + current display configuration
- Shows the weekly view as default (aligned with the main design screen)

### 5.3 — `/config` routes (`app/server/routes/config.py`)

**`GET /config`:** configuration form. Fields:
- Server: host, port
- Display: type, width, height, fullscreen, refresh_interval, eink_model, eink_palette, eink_dither
- Calendars: editable list with add/remove; all model fields for each calendar
- "Test connection" button for CalDAV providers (calls `test_connection()`)

**`POST /config`:**
1. Validates the body with Pydantic
2. Serialises to YAML
3. Overwrites the current config file
4. Sends `SIGHUP` to the Uvicorn process for graceful reload
5. Responds `303 See Other` → redirect to `GET /config` with a confirmation message

**Security:** the `password` field in the form is always of type `password`; in the GET response it is masked (`***`) — never return the password in plaintext via the API.

### 5.4 — Jinja2 templates

#### `base.html`
- Header/content/footer structure with CSS token variables (inline `<style>`)
- Font loading from Google Fonts (Playfair Display, IBM Plex Sans, IBM Plex Mono) with fallback
- Variables: `{{ view_title }}`, `{{ display_type }}`, `{{ current_time }}`
- Interactive footer: 4 buttons as `<button>` elements with inline Tabler SVG icons
- `border-radius: 0`, no shadows, `px` units only
- `data-theme` attribute on `<html>` for night mode toggle (HDMI only)

#### `calendar.html`
- Extends `base.html`
- Weekly view: CSS grid with fixed columns for times and days
- Event blocks: `<div>` with classes `.event`, `.event--selected`, `.event--allday`
- Respects all CSS tokens and visual rules from the design doc
- No third-party JavaScript — only native form interaction and virtual footer buttons

#### `config.html`
- Extends `base.html`
- Display and server fields form
- Calendars section: dynamic list with HTML `<template>` for adding a new calendar
- Minimal client-side validation (HTML5 `required`, `type="url"`, `type="number"`)
- Post-save feedback message via query param `?saved=1`

## Phase 6 — Integration

**Goal:** all components wired together and startable with a single command.

### 6.1 — `app/main.py`

```python
def main():
    args = parse_args()          # --config PATH
    config = load_config(args.config)

    aggregator = CalendarAggregator(config.calendars)

    if config.display.type == "hdmi":
        renderer = ImageRenderer(aggregator, config.display)
        display = HdmiDisplay(config.display, renderer, aggregator)
        display.start()           # pygame loop in separate thread
    elif config.display.type == "eink":
        renderer = ImageRenderer(aggregator, config.display)
        eink_renderer = EinkRenderer(config.display)
        display = EinkDisplay(config.display)
        # periodic loop in separate thread

    app = create_app(config, aggregator)
    uvicorn.run(app, host=config.server.host, port=config.server.port)
```

`SIGTERM` / `SIGINT` handling: stops the pygame display gracefully before terminating Uvicorn.

### 6.2 — Graceful reload via `POST /config`

Uvicorn is started with `app` as a string (`"app.server.app:app"`) to support reload. `SIGHUP` → Uvicorn reloads the application. The pygame display is **not** restarted — only the web server. The new configuration is re-read by the aggregator on the next refresh.
