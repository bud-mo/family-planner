# Piano di Sviluppo — Family Planner v0.1.0

> Versione: 0.1.0  
> Data: 23 maggio 2026  
> Riferimenti: `docs/architecture.md`, `docs/design.md`

---

## Obiettivo della versione

Implementazione completa del sistema funzionante su display HDMI (pygame), con supporto CalDAV iCloud e file ICS locali, server web FastAPI per anteprima e configurazione, e tutte e cinque le viste del calendario (annuale, mensile, settimanale, giornaliera, dettaglio appuntamento).

Il display e-ink è incluso nel perimetro ma trattato come layer di post-processing — l'infrastruttura viene costruita, ma il test su hardware fisico è fuori scope per questa versione.

---

## Vincoli invarianti (da rispettare in ogni fase)

- Nessun `box-shadow`, `text-shadow`, `border-radius` nei template HTML o nel renderer Pillow
- Le librerie Waveshare sono sempre importate dinamicamente, protette da `display.type == "eink"`
- `ImageRenderer` è condiviso da entrambi i display — nessuna duplicazione della logica di rendering
- Le credenziali CalDAV non appaiono mai in log, output API o messaggi di errore
- Tutti i percorsi file usano `pathlib.Path`
- Logging standard (`logging`) — nessun `print` diagnostico
- Type hints obbligatori su tutte le funzioni pubbliche

```python
class ServerConfig(BaseModel):
    host: str = "0.0.0.0"

    fullscreen: bool = False
    type: Literal["hdmi", "eink"] = "hdmi"

    # caldav
    url: str | None = None
    username: str | None = None
    password: str | None = None
    # ics

class AppConfig(BaseModel):
```

## Fase 2 — Layer Calendario

**Goal:** recupero e normalizzazione degli eventi da fonti diverse.

### 2.1 — Classe astratta `CalendarProvider` (`app/calendar/base.py`)

```python
from abc import ABC, abstractmethod
from dataclasses import dataclass
from datetime import datetime

@dataclass
class CalendarEvent:
    uid: str
    title: str
    start: datetime
    end: datetime
    all_day: bool
    location: str | None
    description: str | None
    attendees: list[str]
    recurrent: bool
    color: str              # ereditato dal provider
    calendar_name: str

class CalendarProvider(ABC):
    @abstractmethod
    def fetch_events(self, start: datetime, end: datetime) -> list[CalendarEvent]: ...

    @abstractmethod
    def test_connection(self) -> bool: ...
```

### 2.2 — Provider ICS locale (`app/calendar/ics_provider.py`)

- Legge file `.ics` da `path` (supporta percorsi relativi e assoluti tramite `pathlib.Path`)
- Usa la libreria `icalendar` per il parsing
- Gestisce eventi ricorrenti con espansione nel range `[start, end]`
- Gestisce `VTIMEZONE` e normalizzazione a `datetime` aware
- `test_connection()`: verifica esistenza del file
- Gestione eccezioni: `FileNotFoundError`, `ValueError` per ICS malformato — log e lista vuota, non crash

### 2.3 — Provider CalDAV (`app/calendar/caldav_provider.py`)

- Connessione a `url` con `username` / `password` tramite libreria `caldav`
- Scoperta automatica dei calendari disponibili sull'account
- Recupero eventi nel range `[start, end]` con filtro per data lato server (no download completo)
- **Sicurezza:** la password non appare mai nei log — usare `repr` sicuro o redacting nel logging
- `test_connection()`: tenta un `PROPFIND` leggero, restituisce `bool`
- Gestione eccezioni specifiche: `caldav.DAVError`, `requests.ConnectionError`, `AuthorizationError`
- Timeout configurabile (default: 15 secondi)

### 2.4 — `CalendarAggregator` (`app/calendar/aggregator.py`)

- Istanzia i provider da `list[CalendarConfig]` (factory interna)
- `get_events(start: datetime, end: datetime) -> list[CalendarEvent]`: chiama tutti i provider in parallelo (`ThreadPoolExecutor`), aggrega, ordina per `start`
- Provider falliti: log dell'errore, risultato parziale (non blocca gli altri)
- Cache TTL pari a `display.refresh_interval` per evitare fetch ridondanti su refresh HDMI ravvicinati

**Goal:** tutte le cinque viste renderizzabili come `PIL.Image`.

### 3.1 — Stato di navigazione (`app/renderer/state.py`)

Enum e dataclass per il navigatore:

```python
from enum import Enum, auto
from dataclasses import dataclass, field
from datetime import date

class View(Enum):
    ANNUAL   = auto()
    MONTHLY  = auto()
    WEEKLY   = auto()
    DAILY    = auto()
    DETAIL   = auto()

@dataclass
class NavigationState:
    view: View = View.WEEKLY
    selected_date: date = field(default_factory=date.today)
    selected_event_uid: str | None = None
    detail_scroll_offset: int = 0
    night_mode: bool = False
```

Metodi di navigazione: `navigate_up()`, `navigate_down()`, `navigate_enter()`, `navigate_escape()` — ciascuno restituisce il nuovo `NavigationState` senza mutare lo stato corrente (immutable transitions).

### 3.4 — `ImageRenderer` (`app/renderer/image_renderer.py`)

Classe principale. Dipende da `CalendarAggregator`, `NavigationState`, `DisplayConfig`.

**Struttura interna:**

```python
class ImageRenderer(Renderer):
    def __init__(self, aggregator, config: DisplayConfig, state: NavigationState): ...

    def render(self) -> Image.Image:
        img = Image.new("RGB", (self.width, self.height), self._palette["COLOR_BG"])
        draw = ImageDraw.Draw(img)
        self._draw_header(draw, img)
        self._draw_footer(draw, img)
        self._draw_content(draw, img)
        return img

    def _draw_header(self, draw, img): ...
    def _draw_footer(self, draw, img): ...
    def _draw_content(self, draw, img):
        # dispatch per vista corrente
        match self.state.view:
            case View.ANNUAL:   self._draw_annual(draw, img)
            case View.MONTHLY:  self._draw_monthly(draw, img)
            case View.WEEKLY:   self._draw_weekly(draw, img)
            case View.DAILY:    self._draw_daily(draw, img)
            case View.DETAIL:   self._draw_detail(draw, img)
```

**Metodi per vista — specifiche di rendering:**

#### `_draw_annual`
- Griglia 4×3 di mini-calendari
- Ogni mini-calendario: intestazione mese uppercase `TEXT_SM`, numeri giorni `TEXT_XS`
- Mese selezionato: outline `2px COLOR_RULE_STRONG`
- Giorno corrente: quadrato `16×16px` sfondo `COLOR_ACCENT`, testo `COLOR_BG`
- Festività: numero in `font-weight bold`, punto `·` sotto

#### `_draw_monthly`
- 7 colonne (Lun–Dom), intestazioni uppercase `TEXT_SM`
- Righe settimana separate da `1px COLOR_RULE`
- Settimana selezionata: sfondo `COLOR_BG_ALT`, bordi top/bottom `2px COLOR_RULE_STRONG`
- Oggi: quadrato `28×28px` sfondo `COLOR_ACCENT`
- Giorni con eventi: trattino `—` sotto il numero, `COLOR_INK_MUTED`
- Giorni mese precedente/successivo: `COLOR_INK_FAINT`

#### `_draw_weekly`
- Colonna orario sinistra: larghezza fissa `52px`, `FONT_MONO TEXT_XS COLOR_INK_MUTED`
- Colonne giorno: larghezza uniforme rimanente divisa per 7
- Griglia temporale: 08:00–22:00 default (da config futura)
- Blocchi appuntamento: rettangolo `1px COLOR_RULE_STRONG`, sfondo `COLOR_BG_ALT`
- Appuntamento selezionato: `2px COLOR_RULE_STRONG`, sfondo `COLOR_ACCENT`, testo `COLOR_BG`
- Riga ora corrente: linea `1px COLOR_ACCENT` orizzontale
- Fascia tutto-il-giorno: altezza `24px` sopra la griglia, `1px COLOR_RULE_STRONG` sotto
- Header colonna giorno corrente: inversione cromatica

#### `_draw_daily`
- Fascia sinistra orario: larghezza `56px`, `FONT_MONO TEXT_SM COLOR_INK_MUTED`, allineato a destra
- Ogni appuntamento: blocco con `1px COLOR_RULE` border-top
- Nome: `FONT_BODY TEXT_BASE weight=600`
- Intervallo orario: `TEXT_SM COLOR_INK_MUTED`
- Appuntamento selezionato: sfondo `COLOR_BG_ALT`, bordo sinistro `3px COLOR_RULE_STRONG`
- Slot libero ≥ 60 min: riga `──── Libero ────` in `COLOR_INK_FAINT TEXT_XS`
- Overflow appuntamenti: effetto "pagina" — no scroll, sostituzione intera content area

#### `_draw_detail`
- Titolo: `FONT_DISPLAY TEXT_XL uppercase bold`
- Separatori doppia riga `═` sopra e sotto il titolo
- Righe informative: icona (caricata come PNG/SVG rasterizzato `16px`) + testo `FONT_BODY TEXT_BASE`
- Sezione NOTE: `1px COLOR_RULE` border-top, area scrollabile gestita via `detail_scroll_offset`
- Indicatore overflow `▼` in `COLOR_INK_FAINT` quando le note superano lo spazio

**Font:** caricare da file `.ttf` nella directory `app/assets/fonts/`. Se assente, fallback a font PIL built-in con warning.

**Icone:** rasterizzare i SVG Tabler a `16px` / `20px` / `24px` via Pillow `Image.open()` su PNG preconvertiti in `app/assets/icons/`. Script di conversione separato non è in scope — le icone PNG sono asset statici.

### 3.5 — `EinkRenderer` (`app/renderer/eink_renderer.py`)

Post-processing su `PIL.Image` ricevuto da `ImageRenderer`:

1. Resize alla risoluzione nativa del pannello (`eink_model` → dizionario risoluzioni note)
2. Quantizzazione palette:
   - `bw`: `image.convert("1")` poi `convert("RGB")`
   - `bwr`: palette a 3 colori custom (bianco, nero, rosso)
   - `4gray`: 4 livelli di grigio equidistanti
3. Dithering Floyd-Steinberg: `Image.Dither.FLOYDSTEINBERG` se `eink_dither: true`
4. Restituisce `PIL.Image` pronto per il push al pannello

## Fase 4 — Layer Display

**Goal:** il rendering viene portato a schermo (HDMI) o al pannello fisico (e-ink).

### 4.1 — `HdmiDisplay` (`app/display/hdmi.py`)

```python
class HdmiDisplay:
    def __init__(self, config: DisplayConfig, renderer: ImageRenderer,
                 aggregator: CalendarAggregator): ...

    def start(self) -> None:
        # avvia il loop pygame in thread separato
        threading.Thread(target=self._loop, daemon=True).start()

    def _loop(self) -> None:
        pygame.init()
        flags = pygame.FULLSCREEN if self.fullscreen else 0
        screen = pygame.display.set_mode((self.width, self.height), flags)
        clock = pygame.time.Clock()
        while self._running:
            for event in pygame.event.get():
                if event.type == pygame.QUIT:
                    self._running = False
                elif event.type == pygame.KEYDOWN:
                    self._handle_key(event.key)
            image = self.renderer.render()
            surface = pygame.image.frombuffer(
                image.tobytes(), image.size, image.mode)
            screen.blit(surface, (0, 0))
            pygame.display.flip()
            clock.tick(1 / self.refresh_interval)
        pygame.quit()

    def _handle_key(self, key: int) -> None:
        # mappatura K_ESCAPE→escape, K_UP→up, K_DOWN→down, K_RETURN→enter
        # aggiorna NavigationState e chiama renderer.update_state(new_state)

    def stop(self) -> None:
        self._running = False
```

Mappatura tasti → azioni di navigazione (da `docs/design.md`):

| `pygame.key` | Azione |
|---|---|
| `K_ESCAPE` | `navigate_escape()` |
| `K_UP` | `navigate_up()` |
| `K_DOWN` | `navigate_down()` |
| `K_RETURN` | `navigate_enter()` |

Modalità notte: toggle via tasto `K_n` (HDMI only) — aggiorna `NavigationState.night_mode`.

## Fase 5 — Server Web

**Goal:** anteprima web del calendario e interfaccia di configurazione funzionanti nel browser.

### 5.1 — App FastAPI (`app/server/app.py`)

```python
def create_app(config: AppConfig, aggregator: CalendarAggregator) -> FastAPI:
    app = FastAPI(title="Family Planner")
    app.include_router(index_router)
    app.include_router(config_router)
    templates = Jinja2Templates(directory=Path(__file__).parent / "templates")
    app.state.config = config
    app.state.aggregator = aggregator
    app.state.templates = templates
    return app
```

### 5.2 — Rotta `GET /` (`app/server/routes/index.py`)

- Recupera eventi della settimana corrente da `aggregator`
- Renderizza `calendar.html` con contesto eventi + configurazione display corrente
- Mostra la vista settimanale come default (allineato alla schermata principale del design)

### 5.3 — Rotte `/config` (`app/server/routes/config.py`)

**`GET /config`:** form di configurazione. Campi:
- Server: host, port
- Display: type, width, height, fullscreen, refresh_interval, eink_model, eink_palette, eink_dither
- Calendari: lista editabile con add/remove; per ogni calendario tutti i campi del modello
- Pulsante "Test connessione" per provider CalDAV (chiama `test_connection()`)

**`POST /config`:**
1. Valida il body con Pydantic
2. Serializza in YAML
3. Sovrascrive il file di config corrente
4. Invia `SIGHUP` al processo Uvicorn per riavvio graceful
5. Risponde `303 See Other` → redirect a `GET /config` con messaggio di conferma

**Sicurezza:** il campo `password` nel form è sempre di tipo `password`; nella risposta GET il campo è oscurato (`***`) — mai restituire la password in chiaro via API.

### 5.4 — Template Jinja2

#### `base.html`
- Struttura header/content/footer con variabili CSS token (inline `<style>`)
- Caricamento font Google Fonts (Playfair Display, IBM Plex Sans, IBM Plex Mono) con fallback
- Variabili: `{{ view_title }}`, `{{ display_type }}`, `{{ current_time }}`
- Footer interattivo: 4 tasti come `<button>` con icone Tabler SVG inline
- `border-radius: 0`, nessuna ombra, solo `px` come unità
- Attributo `data-theme` su `<html>` per il toggle notte (solo HDMI)

#### `calendar.html`
- Estende `base.html`
- Vista settimanale: griglia CSS con colonne fisse per orari e giorni
- Blocchi appuntamento: `<div>` con classi `.event`, `.event--selected`, `.event--allday`
- Rispetta tutti i token CSS e le regole visive del design doc
- Nessun JavaScript di terze parti — solo interazione form nativa e tasti virtuali footer

#### `config.html`
- Estende `base.html`
- Form campi display e server
- Sezione calendari: lista dinamica con template `<template>` HTML per aggiunta nuovo calendario
- Validazione lato client minimale (HTML5 `required`, `type="url"`, `type="number"`)
- Messaggio di feedback post-salvataggio tramite query param `?saved=1`

## Fase 6 — Integrazione

**Goal:** tutti i componenti collegati e avviabili con un singolo comando.

### 6.1 — `app/main.py`

```python
def main():
    args = parse_args()          # --config PATH
    config = load_config(args.config)

    aggregator = CalendarAggregator(config.calendars)

    if config.display.type == "hdmi":
        renderer = ImageRenderer(aggregator, config.display)
        display = HdmiDisplay(config.display, renderer, aggregator)
        display.start()           # loop pygame in thread separato
    elif config.display.type == "eink":
        renderer = ImageRenderer(aggregator, config.display)
        eink_renderer = EinkRenderer(config.display)
        display = EinkDisplay(config.display)
        # loop periodico in thread separato

    app = create_app(config, aggregator)
    uvicorn.run(app, host=config.server.host, port=config.server.port)
```

Gestione `SIGTERM` / `SIGINT`: ferma il display pygame gracefully prima di terminare Uvicorn.

### 6.2 — Riavvio graceful via `POST /config`

Uvicorn è avviato con `app` come stringa (`"app.server.app:app"`) per supportare il reload. `SIGHUP` → Uvicorn ricarica l'applicazione. Il display pygame NON viene riavviato — solo il server web. La nuova configurazione viene riletta dall'aggregator al prossimo refresh.

## Fase 7 — Script e Deploy

### 7.1 — `scripts/start.sh`

```bash
#!/usr/bin/env bash
source .venv/bin/activate
python app/main.py --config "${1:-config/default.yaml}"
```

### 7.2 — `scripts/install.sh`

Da eseguire una tantum sul Raspberry Pi:
1. Installa dipendenze di sistema: `python3-pip`, `libsdl2-dev`, `libsdl2-image-dev`, `libsdl2-mixer-dev`, `libsdl2-ttf-dev` (per pygame), SPI tools (per e-ink)
2. Crea virtualenv in `venv/`
3. `pip install -r requirements.txt`
4. Copia `systemd/family-planner.service` in `/etc/systemd/system/`
5. `chmod 600 config.yaml` se presente

### 7.3 — `scripts/deploy.sh`

```bash
#!/usr/bin/env bash
# Uso: ./scripts/deploy.sh pi@<ip>
TARGET="${1:?Usage: deploy.sh user@host}"
rsync -avz --exclude='.git' --exclude='__pycache__' \
    --exclude='.venv' --exclude='venv' \
    ./ "${TARGET}:/home/pi/family-planner/"
ssh "${TARGET}" "cd /home/pi/family-planner && \
    pip install -r requirements.txt --quiet && \
    systemctl daemon-reload && \
    systemctl restart family-planner"
```

### 7.4 — `scripts/setup-autostart.sh`

```bash
#!/usr/bin/env bash
TARGET="${1:?Usage: setup-autostart.sh user@host}"

```
