## Obiettivo della versione

v0.6.0 è una versione di **consolidamento**: non introduce nuove funzionalità utente, ma chiude i rilievi emersi dalla revisione architetturale (`docs/architecture-review.md`). Tre filoni:

1. **Sicurezza** — eliminare l'esposizione in chiaro delle credenziali via API e introdurre una protezione opzionale sulle rotte di configurazione.
2. **Correttezza runtime** — sistemare le incoerenze del reload SIGHUP, l'ordine di inizializzazione del button handler, il parametro morto `last_push_at`, e i campi persi dal form `/config`.
3. **Robustezza, pulizia e allineamento documentazione** — dipendenze esplicite, eviction cache, sync icone, e soprattutto riportare `architecture.md`, `README.md` e `AGENTS.md` in pari con il codice reale.

**Criterio di chiusura della versione:** al termine di tutte le fasi, ogni rilievo di `docs/architecture-review.md` risulta *risolto* oppure *deferito con motivazione tracciata* in `docs/architecture.md` (sezione "Debito tecnico noto"). A quel punto `architecture-review.md` può essere eliminato (Fase 6).

## Vincoli invarianti

Restano validi i vincoli delle versioni precedenti. In particolare per v0.6.0:

- **Nessuna regressione funzionale**: la schermata Home, l'artwork (B), il ritorno al planner (A), lo shutdown (D), l'anteprima web e il reload graceful devono comportarsi esattamente come prima, salvo dove esplicitamente modificato.
- **Import hardware sempre lazy**: nessuna modifica deve introdurre un import di `waveshare_epd`, `inky` o `gpiod` a livello di modulo.
- **`render()` resta il solo punto di calcolo dei `Rect`** (vincolo già vero per i layout; vedi nota in Fase 5 sul disallineamento del *principio* documentato).
- **Le credenziali non compaiono mai in log o messaggi d'errore** — il rilievo di sicurezza riguarda solo le rotte HTTP, non i log (già corretti).
- **Comportamento multipiattaforma invariato**: tutto deve continuare a girare su macOS/Linux senza hardware.

## Fase 1 — Sicurezza

**Goal:** nessuna rotta HTTP espone credenziali in chiaro senza autenticazione; le rotte di configurazione possono essere protette; l'esposizione su `0.0.0.0` senza protezione produce un warning evidente all'avvio.

> **Decisione di design.** Il server deve restare raggiungibile in LAN su RPi headless, quindi non si forza il bind su `127.0.0.1`. Si adotta invece una **Basic Auth opzionale** sulle rotte sensibili più la **sanitizzazione del download**. Alternativa considerata e scartata: bind di default su loopback (rompe lo use-case headless documentato). L'alternativa è comunque documentata in `architecture.md` per chi preferisce isolare la rete.

### 1.1 — Schema config: credenziali di accesso opzionali

In [config.py](../app/config.py#L14) estendere `ServerConfig`:

```python
class ServerConfig(BaseModel):
    host: str = "0.0.0.0"
    port: int = 8080
    # Basic Auth opzionale sulle rotte /config e /api/config/*.
    # Se entrambi None → rotte aperte (con warning all'avvio se host non è loopback).
    auth_username: str | None = None
    auth_password: str | None = None
```

Aggiornare `config/default.yaml` con i campi commentati (default `null`), e trattare `auth_password` come credenziale: va scrubato esattamente come le password CalDAV (vedi 1.3).

### 1.2 — Dependency di autenticazione

Creare `app/server/auth.py` con una dependency FastAPI riusabile:

```python
from __future__ import annotations
import secrets
from fastapi import Depends, HTTPException, Request, status
from fastapi.security import HTTPBasic, HTTPBasicCredentials

_security = HTTPBasic(auto_error=False)

def require_config_auth(
    request: Request,
    credentials: HTTPBasicCredentials | None = Depends(_security),
) -> None:
    """Protegge le rotte di configurazione se server.auth_* è impostato.

    No-op se auth non è configurata (rotte aperte). Confronto in tempo costante.
    """
    cfg = request.app.state.config.server
    if not cfg.auth_username or not cfg.auth_password:
        return
    ok = (
        credentials is not None
        and secrets.compare_digest(credentials.username, cfg.auth_username)
        and secrets.compare_digest(credentials.password, cfg.auth_password)
    )
    if not ok:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Autenticazione richiesta.",
            headers={"WWW-Authenticate": "Basic"},
        )
```

### 1.3 — Applicare auth e sanitizzare il download

In [config.py routes](../app/server/routes/config.py):

- Aggiungere `dependencies=[Depends(require_config_auth)]` a **tutte** le rotte del router di config: `GET /config`, `POST /config`, `GET /api/config/download`, `POST /api/config/upload`, `POST /api/test-weather`, `POST /api/test-connection`. (Le rotte di sola anteprima `/`, `/preview.png`, `/preview-eink.png` restano **aperte**: mostrano solo il calendario, già privo di credenziali.)
- **`config_download`** ([config.py:257](../app/server/routes/config.py#L257)): non servire più il file grezzo. Generare al volo un YAML sanitizzato che azzera ogni `password` CalDAV e `auth_password`, riusando la logica di `_safe_config_dict`:

```python
@router.get("/api/config/download")
async def config_download(request: Request) -> Response:
    config: AppConfig = request.app.state.config
    safe = _safe_config_dict(config)          # password CalDAV già azzerate
    safe["server"]["auth_password"] = ""       # scruba anche la password di accesso
    body = yaml.dump(safe, allow_unicode=True, sort_keys=False)
    return Response(
        content=body,
        media_type="application/x-yaml",
        headers={"Content-Disposition": 'attachment; filename="config.yaml"'},
    )
```

> Nota: il backup scaricato richiederà di reinserire le password al ripristino. È il compromesso corretto: nessun segreto lascia mai il dispositivo via HTTP.

- Estendere `_safe_config_dict` ([config.py:32](../app/server/routes/config.py#L32)) perché azzeri anche `data["server"]["auth_password"]`, così la GET `/config` non rivela la password di accesso.

In [main.py](../app/main.py) (dopo `load_config`, prima di avviare il server), aggiungere:

Fix — usare la stessa indirezione a lista già adottata per `_eink_renderer_ref`:

1. In [main.py](../app/main.py#L407) introdurre `_renderer_ref: list = [renderer]` subito dopo aver creato `renderer`.
2. Cambiare la firma di `_eink_loop` ([main.py:166](../app/main.py#L166)) da `renderer: PillowEinkRenderer` a `renderer_ref: list`, e all'interno del loop usare `renderer_ref[0].render(state, events)` ([main.py:230](../app/main.py#L230)).
3. Passare `_renderer_ref` (non `renderer`) nell'avvio del thread ([main.py:435](../app/main.py#L435)).

### 3.2 — Eviction della cache aggregatore (§4.7)

[aggregator.py:55](../app/calendar/aggregator.py#L55): la cache keyed su `(start, end)` accumula una entry/giorno. Aggiungere pruning delle entry scadute in `get_events`, sotto lock:

```python
def get_events(self, start, end):
    cache_key = (start, end)
    now = time.monotonic()
    with self._cache_lock:
        # Eviction: rimuovi le entry più vecchie del TTL
        expired = [k for k, (ts, _) in self._cache.items() if now - ts >= self._cache_ttl]
        for k in expired:
            del self._cache[k]
        entry = self._cache.get(cache_key)
        if entry is not None and now - entry[0] < self._cache_ttl:
            return entry[1]
    events = self._fetch_all(start, end)
    with self._cache_lock:
        self._cache[cache_key] = (time.monotonic(), events)
    return events
```

**Accettazione:** test unitario che, con `cache_ttl` basso, verifica che `_cache` non cresca oltre 1–2 entry dopo molte chiamate con chiavi diverse e tempo avanzato (monkeypatch di `time.monotonic`).

### 3.3 — Auto-sync `icon_catalog.WEATHER_ICONS` (§4.8)

[icon_catalog.py:17](../app/renderer/icon_catalog.py#L17) elenca a mano icone (`bolt`, `cloud-snow`, `cloud-storm`) non usate da `_WMO_TO_ICON`. Eliminare la sincronizzazione manuale derivando il set dalla fonte reale:

```python

```

Verificare assenza di cicli di import (`open_meteo` importa da `tokens` e `weather.provider`; `icon_catalog` importa da `emoji_icons` + `open_meteo` → nessun ciclo). Se si preferisce evitare l'import di un simbolo privato cross-modulo, promuovere `_WMO_TO_ICON` a `WMO_TO_ICON` (pubblico) in `open_meteo.py` e aggiornare i riferimenti interni.

**Accettazione:** `python -c "from app.renderer.icon_catalog import WEATHER_ICONS; print(sorted(WEATHER_ICONS))"` → `['cloud', 'cloud-rain', 'snowflake', 'sun']`; gli script di generazione asset non producono più icone meteo inutilizzate.

### 3.4 — Eventi all-day indipendenti dalla longitudine (§4.9)

[base.py:8](../app/calendar/base.py#L8) mappa gli all-day a mezzanotte UTC; il raggruppamento agenda usa `start.astimezone(tz).date()` ([pillow_eink_renderer.py:820](../app/renderer/pillow_eink_renderer.py#L820)), che per timezone a ovest di UTC slitterebbe al giorno precedente. Fix mirato nel raggruppamento e nella formattazione: per gli all-day usare la data nativa, senza conversione TZ.

```python
# in _draw_agenda e _format_event_short
evt_date = evt.start.date() if evt.all_day else evt.start.astimezone(self._tz).date()
```

(`evt.start` per gli all-day è midnight UTC, quindi `.date()` restituisce la data originale dell'evento.)

**Accettazione:** un evento all-day del 15/06 risulta sotto il 15/06 sia con `timezone: Europe/Rome` sia con `timezone: America/Los_Angeles` (test parametrico).

## Fuori scope

- Nuove funzionalità utente (nessuna in v0.6.0).
- Autenticazione avanzata (OAuth, sessioni): la Basic Auth opzionale è sufficiente per una LAN domestica; soluzioni più robuste sono rimandate.
- Partial refresh e-ink e altre ottimizzazioni di rendering.
- Internazionalizzazione oltre l'italiano: `locale_it.py` consolida le stringhe ma non introduce un layer i18n generico.
- Riscrittura dei test visivi: i test esistenti restano la regression guard; se ne aggiungono solo di nuovi (cache, all-day TZ).
