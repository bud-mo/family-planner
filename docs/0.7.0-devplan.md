# Development Plan — Family Planner v0.7.0

> Version: 0.7.0
> Date: June 20, 2026
> References: `docs/architecture.md`, `docs/design.md`, `docs/embedded.md`, `docs/spectra_6.md`, `docs/0.6.0-devplan.md`

---

## Version Objective

v0.7.0 is a **scope-reduction** release: it **removes HDMI monitor support entirely**. From this version on, the only supported output is the **e-ink panel** (Waveshare EPD models + Pimoroni Inky Impression Spectra 6). The browser preview (`/`, `/preview.png`, `/preview-eink.png`) and the web configuration UI remain unchanged — they are not "displays" but development/operations tools.

Rationale:

- The HDMI path (`pygame`/SDL2 main-thread window) duplicated the display loop, doubled the runtime surface (two refresh loops, two reload paths, two button-input mechanisms), and required SDL2 system packages + the `pygame` dependency that have no use on the target hardware.
- The product is an e-ink wall planner; the HDMI window was a development convenience now fully served by the **web preview** (which renders the exact same `PillowEinkRenderer` output).
- Removing it simplifies `main.py` (single display loop), the config schema (`width`/`height`/`fullscreen`/`type` become e-ink-derived or disappear), and the installer (no SDL2, no `video` group for KMS).

**Release closure criterion:** the application no longer imports `pygame`, contains no `HdmiDisplay`, and runs only the e-ink loop (or web-server-only mode when no panel is attached). `grep -rn "hdmi\|pygame\|HdmiDisplay\|SDL" app/ scripts/ systemd/ requirements.txt` returns only intentional historical mentions (e.g. changelog), and the full test suite is green.

## What Is Removed vs. What Stays

| Concern | v0.6.0 | v0.7.0 |
|---|---|---|
| HDMI pygame window (`HdmiDisplay`) | supported | **removed** |
| `pygame` dependency / SDL2 packages | required | **removed** |
| `display.type` (`hdmi`\|`eink`) | config field | **removed** (always e-ink) |
| `display.width` / `display.height` | user-set (HDMI) / derived (e-ink) | **derived** from panel model + rotation |
| `display.fullscreen` | config field | **removed** |
| pygame keyboard input (`B`/`D`/`q`/`F4`) | supported | **removed** (physical Inky buttons only) |
| E-ink loop (`_eink_loop`) | supported | **stays — sole display path** |
| Inky physical buttons (A/B/D) | supported | **stays** |
| Web preview + config UI | supported | **stays** |
| Web-server-only mode (no panel) | implicit HDMI fallback | **explicit** fallback when panel absent |

## Invariant Constraints

Constraints from previous versions remain valid. In particular for v0.7.0:

- **No regression of e-ink behavior**: the Home screen, artwork mode (B), return to planner (A), shutdown (D), content-signature change detection, SIGHUP reload, and the web preview must behave exactly as before.
- **Hardware imports remain lazy**: `waveshare_epd`, `inky`, `gpiod` are still imported only inside the e-ink drivers/handlers, never at module top level.
- **Cross-platform dev still works**: the app must still import and run on macOS/Linux without any panel attached (web-server-only mode), now **without** requiring SDL2/pygame.
- **Single rendering source unchanged**: `PillowEinkRenderer.render()` remains the only image producer; the web preview and the e-ink loop both consume it.
- **No new user-facing features**: this release only removes a code path and simplifies configuration.

## Phase 2 — Configuration Schema

**Goal:** the config no longer carries HDMI-only fields. Canvas dimensions are derived from the panel model + rotation (single source of truth: `EINK_RESOLUTIONS`).

### 2.1 — Simplify `DisplayConfig`

In [app/config.py](../app/config.py#L23):

- Remove `type` (always e-ink now), `width`, `height`, and `fullscreen`.
- Keep `layout`, `show_buttons` (web-preview overlay only — see note), `eink_model`, `eink_palette`, `eink_dither`, `eink_saturation`, `rotation`.

```python
class DisplayConfig(BaseModel):
    layout: Literal["portrait", "landscape"] = "landscape"
    show_buttons: bool = False      # web-preview navigation overlay (browser only)
    eink_model: str = "7in5_V2"
    eink_palette: Literal["bw", "bwr", "4gray", "spectra6"] = "bw"
    eink_dither: bool = True
    eink_saturation: float = 0.5
    rotation: Literal[0, 90, 180, 270] = 0

    @property
    def resolution(self) -> tuple[int, int]:
        """Canvas (width, height) derived from panel model + rotation."""
        from app.renderer.eink_renderer import EINK_RESOLUTIONS
        w, h = EINK_RESOLUTIONS[self.eink_model]
        if self.rotation in (90, 270):
            w, h = h, w
        return w, h
```

> **Validation:** add a `field_validator("eink_model")` (or model validator) that rejects models not present in `EINK_RESOLUTIONS`, replacing the old free-form `str`. This turns the previously runtime-only error (`EinkRenderer.__init__`) into a load-time error.

> **`show_buttons` decision:** it drives an on-screen overlay used only by the browser preview (`templates.env.globals["show_buttons"]`). It is **not** HDMI-specific, so it stays. If a future release drops the overlay too, remove it then.

### 2.2 — Update `config/default.yaml`

Remove `type`, `width`, `height`, `fullscreen` from the `display` block:

```yaml
display:
  layout: landscape
  show_buttons: false
  eink_model: 7in5_V2
  eink_palette: bw
  eink_dither: false
  eink_saturation: 0.5
  rotation: 0
```

> The working tree also carries `eink_gamma` / `eink_brightness` comments not declared in `DisplayConfig` (read via `getattr` in the renderer). Leave them as-is — out of scope for HDMI removal.

### 2.3 — Backward compatibility for existing config files

Existing on-disk configs may still contain `type: hdmi`, `width`, `height`, `fullscreen`. Pydantic v2 ignores unknown keys by default, so load won't fail — but a user with `type: hdmi` would silently get e-ink. Add a one-line migration warning in `load_config` ([config.py:117](../app/config.py#L117)) after parsing:

```python
if isinstance(raw, dict) and raw.get("display", {}).get("type") == "hdmi":
    logger.warning(
        "display.type 'hdmi' is no longer supported (removed in v0.7.0) — "
        "using the e-ink panel. Remove 'type', 'width', 'height', 'fullscreen' "
        "from the display section of %s.",
        path,
    )
```

**Acceptance — Phase 2:**

```bash
python -c "from app.config import DisplayConfig; print(DisplayConfig().resolution)"   # -> (800, 480) for 7in5_V2
python -c "from app.config import load_config; load_config('config/default.yaml')"     # loads, no error
# loading a legacy config with type: hdmi -> WARNING, e-ink used
```

## Phase 3 — Renderer / Palette Simplification

**Goal:** the renderer no longer branches on display type. Output is always the e-ink palette at the panel resolution.

### 3.1 — Canvas size from panel, not config dimensions

In [pillow_eink_renderer.py:84](../app/renderer/pillow_eink_renderer.py#L84): replace

```python
self._size = (config.display.width, config.display.height)
```

with

```python
self._size = config.display.resolution     # derived from panel model + rotation
```

This removes the renderer's dependency on the now-deleted `width`/`height` fields and guarantees the preview always matches the real panel.

### 3.2 — Remove `_display_type` branching

`display_type` is threaded into `resolve_palette` ([palette.py:99](../app/renderer/palette.py#L99)) and `RenderContext.is_eink` ([context.py:128](../app/renderer/components/context.py#L128)); it is always `"eink"` now.

- In [pillow_eink_renderer.py:86](../app/renderer/pillow_eink_renderer.py#L86): remove `self._display_type`. Update the two call sites ([:132](../app/renderer/pillow_eink_renderer.py#L132), [:261](../app/renderer/pillow_eink_renderer.py#L261)) accordingly.
- In [palette.py](../app/renderer/palette.py#L99): drop the `display_type` parameter and the `if display_type != "eink":` branch (dead code). `resolve_palette(eink_palette)`.
- In [components/context.py](../app/renderer/components/context.py#L116): remove the `display_type` parameter; set `self.is_eink = True` (or drop `is_eink` and inline `True` at its readers — check usages first with `grep -rn "is_eink"`). Prefer keeping `is_eink = True` as a named constant to minimize churn in component code.

> Verify the non-eink palette branch removed in `resolve_palette` had no other behavioral role (it only returned the standard RGB palette for the HDMI window). The browser preview already renders via the e-ink palette path (`/preview.png` uses the same renderer), so this is purely dead-code removal.

## Out of Scope

- New e-ink features, new panel models, or partial-refresh optimizations.
- Removing the browser preview or the web configuration UI — both stay (they are the dev/ops replacement for the HDMI window).
- Removing `show_buttons` — it is a browser-preview overlay, not HDMI-specific.
- Internationalization, security, or rendering changes beyond what HDMI removal directly touches.
- Migrating the `eink_gamma` / `eink_brightness` YAML comments into the typed schema (separate cleanup).
